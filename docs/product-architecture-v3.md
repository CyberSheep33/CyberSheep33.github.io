# CyberSheep 服务门户产品与架构规范 v3

> 状态：已确认，作为后续重构与内容维护的主规范。
> 更新日期：2026-08-28。

## 1. 产品定位

CyberSheep 不是单纯的品牌展示页，而是围绕“让用户顺利开始并持续使用 AI 服务”构建的一站式服务门户。

核心用户路径：

1. 访问 CyberSheep，了解可获得的服务；
2. 前往 Sheep AI Plus 注册账号并创建 API Key；
3. 在模型广场查找模型、调用端点、分组与估算价格；
4. 在快速开始中选择工具、模型和可用配置方式；
5. 按教程完成配置并开始使用；
6. 遇到问题时，在公告与帮助中搜索已有解决方案；
7. 通过博客与项目入口继续了解 AI 知识、工具与社区成果。

## 2. 产品原则

- **用户任务优先**：导航和页面顺序围绕注册、选模型、选工具、完成配置、解决问题展开。
- **单一数据源**：导航、项目、公告元数据、教程关系和模型分组不得在多个页面重复维护。
- **只发布有效路线**：快速开始只展示经过确认的“工具 × 模型 × 配置方式”组合。
- **静态优先**：最终产物保持纯 HTML、CSS、JavaScript，可由 GitHub Pages 直接托管。
- **内容与外壳分离**：公共布局、导航、列表和关联关系自动生成；正文允许按内容自由设计。
- **可追溯**：模型数据、教程适用版本和公告更新时间必须可追踪。
- **渐进增强**：JavaScript 提升筛选和交互，但核心入口与正文必须保持清晰、可访问。
- **不破坏既有链接**：重构期间保留已经发布的页面 URL。

## 3. 信息架构

### 3.1 首页

首页按用户路径组织：

1. Hero：说明本站能帮助用户完成什么；
2. Sheep AI Plus：注册、控制台和 API Key 引导；
3. 模型广场：模型、分组、价格与调用端点入口；
4. 快速开始：按目标工具进入教程；
5. 最新公告：自动展示最新三条；
6. 项目展示：分为官方项目与精选创作者项目；
7. 博客与知识：进入独立博客导航页；
8. GitHub、社区与联系方式。

首页只承担解释、推荐和分流，不承载完整教程或完整公告。

### 3.2 模型广场

- 默认展示最新清洗数据；
- 支持搜索、品牌、模型类型、标签和开放分组筛选；
- 详情展示调用端点、基础价格和分组估算价格；
- 页面明确显示数据版本日期；
- 保留历史快照和相邻版本维护日志，用于溯源与分析；
- 价格始终标注“以平台实际扣费为准”。

### 3.3 快速开始

快速开始采用三维内容模型：

- 工具：Claude Code、Codex、OpenCode、Hermes、Reasonix、CLion 插件等；
- 模型：原生模型、DeepSeek 和其他兼容模型；
- 配置方式：配置文件、CC Switch、本地路由、内置配置面板、插件设置面板等。

用户路径为“选择工具 → 选择模型 → 选择该组合实际支持的配置方式 → 阅读教程”。详细规则见 `quickstart-content-model.md`。

### 3.4 公告与帮助

公告同时承担服务公告、更新说明、故障排查、常见问题和使用技巧。列表页应支持分类、关键词和搜索扩展。

公告正文继续使用富 HTML；公共页面外壳、元数据、列表、首页最新三条、上下篇和相关推荐统一维护。详细规范见 `announcement-html-standard.md`。

### 3.5 项目

项目分成两类：

- `official`：CyberSheep / SheepAI-Lab 官方或自有项目；
- `curated`：精选创作者的优质开源项目。

首页展示精选条目；数据增多后可直接生成独立项目页。项目链接、作者、标签和归属只在结构化数据中维护。

### 3.6 博客与知识

博客页只做精选、分类和外链导航，不复制外部文章正文。内容分为：

- 平台入口：CSDN、知乎、微信公众号、掘金、个人博客等；
- 优质博主：简介、擅长领域和平台主页；
- 精选博文：标题、摘要、作者、主题和原文链接。

未提供真实链接前不得生成虚构博主或文章。

## 4. 数据与代码边界

```text
data/                     人工或 AI 维护的结构化数据
  site.json               品牌、导航与全局链接
  projects.json           官方与精选项目
  announcements.json      公告列表和关联元数据
  tutorials-*.json        工具、模型、配置方式和有效路线
  blogs.json              平台、博主和精选文章
  model-snapshots/        每周模型历史快照与维护日志

assets/site-data.js       由脚本生成，供 file:// 与 GitHub Pages 读取
scripts/build-site-data.py 数据校验与浏览器数据生成
scripts/update-models.py   模型备份、清洗、对比和发布
scripts/validate-site.py   全站结构、链接和安全约束校验
```

JSON 是维护源；生成的 JavaScript 快照是浏览器消费格式。这样既保持本地双击可用，也避免在多个 JS 文件中重复维护数据。

## 5. 设计系统

- 延续青绿、暖白和深青黑的统一色系；不增加无业务含义的第二强调色；
- 使用现有 CSS 变量和浅/深主题机制；
- 正文最大阅读宽度约 65 个中文字符；
- 大标题使用紧凑字距与平衡换行，数据使用等宽字体或等宽数字；
- 交互组件必须提供 hover、active、focus、loading、empty 和 error 状态；
- 卡片只在表达内容边界或层级时使用，不把所有元素都装进相同玻璃卡片；
- 动画只使用 transform 和 opacity，并尊重 `prefers-reduced-motion`；
- 移动端以 375px 为最低验收宽度；
- 页面必须具有返回路径、清晰当前位置和键盘可用的焦点样式。

## 6. 内容更新流程

### 新教程

1. 在工具、模型和配置方式数据中确认实体存在；
2. 创建一条有效教程路线；
3. 按教程规范制作正文；
4. 记录来源、适用版本、验证日期和维护状态；
5. 运行数据构建与全站校验；
6. 目验桌面、移动和深色主题。

### 新公告

1. 创建公告 HTML；
2. 在 `data/announcements.json` 添加元数据；
3. 使用公告命名空间隔离私有 CSS/JS；
4. 运行构建后，首页、公告中心和上下篇自动更新；
5. 执行可访问性与移动端目验。

### 新项目或博客链接

只修改对应 JSON 数据；页面列表与首页推荐自动读取数据。

### 新模型数据

执行 `python3 scripts/update-models.py pricing.json`，不得直接手改生成快照。

## 7. 发布质量门槛

- 所有 JSON、Python 和 JavaScript 语法通过；
- 教程路线引用的工具、模型、配置方式和页面均存在；
- 不允许发布不兼容的 CC Switch 路线；
- 公告 slug 唯一且详情页存在；
- 所有站内链接有效；
- 无 API Key、Token 或敏感信息硬编码；
- 模型更新必须生成版本元数据、用户公告和维护日志；
- 首页、快速开始、公告、博客和模型广场均有空状态；
- Git 工作区中的生成数据与源数据保持同步。
