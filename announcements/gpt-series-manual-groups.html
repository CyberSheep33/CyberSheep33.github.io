GPT 系列使用建议 · 2026-08-31

Codex 高效省钱指南：手动分组 + $sol-luna

一套配置同时照顾价格、模型兼容性和任务质量：关闭智能路由，勾选低倍率的 Codex-Gpt 分组，再补充至少一个支持 Luna 的 Azure-Gpt 分组；遇到复杂任务时，用 $sol-luna 让智能体按难度分工。

先把 API Key 配成“低价组合”

关键不是只选一个分组，而是一次勾选 4～5 个低倍率分组，并让其中至少一个能够调用 Luna。

01
创建 API Key在 Sheep AI Plus 创建用于 Codex 的密钥，并进入分组设置。
02
关闭智能路由将 Key 的分组策略改为手动选择，把可用范围限定在你主动勾选的低倍率分组内。
03
勾选五个推荐分组选择 Codex-Gpt-1/2/3 与 Azure-Gpt-2/3。前三个倍率更低，后两个为 Luna 保留可用通道。
04
先小规模实测分别调用 Sol、Terra、Luna，确认可用性、延迟和消费日志，再按实际体验删减或替换分组。

为什么要混选两类分组

截至本次数据快照，最便宜的 Codex-Gpt 系列不能调用 Luna。只选它们会失去低成本模型，因此需要再勾选支持 Luna 的分组。

按任务选择模型

分组组合解决“从哪里调用”，模型选择解决“把什么任务交给谁”。下面是依据平台定位整理的起步建议。

gpt-5.6-sol负责规划、关键决策与最终复核。适合复杂、高影响或质量优先的任务，但不必让它包办全部执行。
gpt-5.6-terra负责跨模块、长上下文或仍有一定歧义的执行工作，在质量与成本之间取得平衡。
gpt-5.6-luna负责边界清晰、可验证、批量或机械性的工作，用较低模型倍率完成日常执行。

再用 $sol-luna 自动组织分工

推荐安装 codex-sol-luna 技能

按照 yangphere/codex-sol-luna 项目说明完成安装。给智能体分配复杂任务时，在需求开头显式写入：

$sol-luna 请分析这个项目并完成重构，验证后给出结果
  • Sol 统一控制理解目标、拆分任务、安排阶段并审核实际结果。
  • Terra 处理难题承接跨模块、长上下文或判断空间较大的执行任务。
  • Luna 批量执行承接清晰、低歧义、机械或高吞吐任务，并提供验证证据。

价值不在于“所有任务都用最强模型”，而在于把昂贵算力集中到规划、难题和复核，把常规执行交给更低成本的模型。是否启用并行与具体模型分配仍由任务复杂度决定，实际体验也会受渠道可用性影响。
